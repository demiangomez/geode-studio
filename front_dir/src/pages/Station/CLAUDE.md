# Station detail tabs

Station detail lives at `/:nc/:sc` (network code / station code). Tabs: **rinex, sources, people, visits, timeseries, events**, plus the station overview/header. It concentrates the heaviest features (ETM/time series, station report, station-info form), so the quirks here matter.

## Time series / ETM (the heaviest area)

- **`TimeSeries.tsx`** is the page. **Migrated to TanStack Query** (`src/hooks/queries/useStationTimeSeries.ts`, `useTimeSeriesConfig.ts`): the plot is a `useQuery` keyed on an `appliedParams` snapshot (the modal mutates a separate live `params`; the plot only refetches when `appliedParams` changes — solution/stack change or "Apply parameters"), the JSON export is a `useMutation`, and solutions/stacks are query hooks. `buildTimeSeriesParams` centralizes the empty-strip + `yyyy-mm-dd`→`yyyy/mm/dd` conversion and maps the form keys to the GET param names. The **adjustment parameters now go to the GET too**: `least_squares_strategy`→`adjustment_model`, `covariance_model`→`covariance_function`, `default_relaxations`→`relaxation`, plus `fit_window_start`/`fit_window_end` (sent **both or neither** — one alone is a 400; accepts decimal-year `2012.0` or a `YYYY/MM/DD` date). `covariance_function` is omitted under `ROBUST_LEAST_SQUARES` (the UI disables it there).
  - `getStationTimeSeriesService(api, id, params, json)` returns `{ etm_params: TimeSeriesParamsData, time_series: string, download_filename, debug_output }`. `etm_params` carries `polynomial`, `periodic`, `jumps`. **`debug_output`** is the console log of the ETM run (the backend captures the `geode.etm` logger, same lines as `PlotETM.py -v debug`) — the `CommandLineIcon` next to the `BookmarkIcon` opens `EtmDebugOutputModal` (read-only `<pre>` + `CopyButton`) with the output of the current plot query. A **400 can carry `debug_output` too** when the ETM ran partially before failing (e.g. invalid GAMIT stack → the lines up to where it stopped), so the page reads it from `tsData` **or** from `ApiError.response.debug_output`; the icon is always rendered but **disabled** while the query is fetching or when neither has it (a params-validation 400 has none).
  - **Solutions come from the backend** (`useSolutionTypes` → `GET api/time-series-config/solution-types`: GAMIT, PPP, NGL, DRA) — never hardcode the solution list.
  - **`stack`** is empty for every solution except **GAMIT**, which uses a real stack name (`useStackNames` → `getStackNamesService`). The stack selector only shows for GAMIT.
  - GET time-series params: required `solution, stack(if GAMIT), residuals, missing_data, plot_outliers, plot_auto_jumps, no_model, remove_jumps, remove_polynomial`; new optional plot params `remove_periodic`, `remove_stochastic` (**the param is `remove_stochastic`**, but the checkbox label is still "REMOVE STOCHASTIC NOISE"); optional window `date_start/date_end`; `json` toggles PNG vs JSON.
  - Date fields are **Year + DOY pairs**. Use `GregorianDatePicker` (which wraps `dateFromDay`/`dayFromDate` from `@utils`). Backend speaks `mm/dd/yyyy`, HTML inputs `yyyy-mm-dd`; conversion is a `/-/g` replace around `TimeSeries.tsx:119-127`. Centralize date handling in the shared picker rather than re-implementing.
- **`@components/TimeSeriesParams.tsx`** renders the three ETM tables (polynomial, periodic, jumps) **inline — not the generic `Table` component**. Jump action states `'-'` / `'+'` / `'A'` drive icon visibility and row color. Reset/deactivate/delete/activate actions live here.
- **`@components/TimeSeriesConfigModal.tsx`** is the add/edit/activate modal for a polynomial/periodic/jump row. `GregorianDatePicker` is integrated here for Year/DOY. Edit branch loads `valueToModify` into the form reducer (excluding `fit`/`metadata`).
- **`@components/modals/Station/StationSeriesFiltersModal.tsx`** is the "Plot/Adjustment Parameters" modal. Plot-filter checkboxes render **dynamically from `formState` (`SERIES_FILTERS_STATE`)** (with a `LABEL_OVERRIDES` map for the non-derivable labels). The adjustment dropdowns **LEAST SQUARES STRATEGY** and **COVARIANCE** are now populated from the backend via `useAdjustmentOptions` (`GET api/time-series-config/adjustment-options` → `adjustment_models` / `covariance_functions`); their option `value` is the backend `type` (e.g. `ROBUST_LEAST_SQUARES`). Interdependent rules: PLOT OUTLIERS enables MISSING DATA; `ROBUST_LEAST_SQUARES` disables COVARIANCE + REMOVE STOCHASTIC NOISE. `DEFAULT RELAXATIONS` is a list-builder (add chips of floats, removable) serialized to the GET as `relaxation=0.3,0.5`.
- **`@components/TimeSeriesParams.tsx`** also renders the **"COPY TRAJECTORY PARAMETERS TO OTHER SOLUTIONS"** checkbox. It is a **persisted, confirmed toggle**: initial `checked` comes from `etm_params.copy_params` in the time-series GET. Clicking the checkbox does **not** change it immediately — it opens the `ConfirmDeleteModal` (`type="copy_sync"`, warning variant, "Sync" button) holding the pending value. **On confirm** it calls `setCopyParamsService` (`POST api/time-series-config/{id}/{solution}/set-copy-params` `{copy_params}`); only on success is the checkbox applied and the **backend's `message`** shown in the modal's Alert. **On cancel** the checkbox stays as-is. Because enabling copies the current solution's params to the others **in the DB**, a successful enable flags a refresh that runs **only when the modal is closed** (`closeModal` → `onCopyParamsSynced` → parent `invalidateQueries(["stationTimeSeries", stationId])`) — deferring it is deliberate: invalidating while the modal is open would refetch the active solution, unmount `TimeSeriesParams` (it lives under `{!loading && …}`), and the success message would never be seen. Each solution has its own query-key entry, so all of them refetch fresh.
- Form state for all of the above uses **`useFormReducer`** with templates in `src/utils/reducerFormStates.tsx` (`SERIES_FILTERS_STATE`, `SERIES_JUMP_DATA`, `SERIES_POLYNOMIAL_DATA`, `SERIES_PERIODIC_DATA`). Adding a field there flows it into the params object automatically.
- Modal trigger convention: `setModalType({ table, type })` → `useEffect` → `showModal(id)`. **Editing a jump now uses an atomic backend endpoint**: `putTimeSeriesJumpService` → `PUT api/time-series-config/{id}/{solution}/set-jumps` (same path/stack query as the POST create) with body = the new jump fields **plus `old_Year`/`old_DOY`** (from `valueToModify`, the original row); the backend deletes the old jump and creates the new one. `TimeSeriesConfigModal.postData()` switches to the PUT service when `type.type === "edit"` && `table === "jumps"` (add still POSTs). `ConfigJumpData` has a duplicate `type` field in the interface (number vs string) — the edit pre-selects the jump-type `<select>` from `type_name`.

## Other tabs

- **Rinex tab** (`Rinex/Rinex.tsx` + `RinexTable.tsx`) — el listado sigue legacy (`useApi`+`useEffect`, flag `shouldFetchRinex`). La columna **DOWNLOAD** por fila baja el archivo vía `useDownloadRinex` (`useMutation`, `hooks/queries/useRinex.ts`): el spinner de la fila se resuelve con `variables.api_id` mientras `isPending`, y los otros botones se deshabilitan para no disparar descargas en paralelo (geode las trae de la fuente remota, tardan). Errores: `Toast` local con el detail del back; el 403 lo pinta el toast global.
- **Sources** (`Sources.tsx`) — **migrada a TanStack Query** (`src/hooks/queries/useSources.ts`). Una sola tabla, RINEX Sources (editable, la de siempre); la metadata de la estación **no es una segunda tabla** — cada fila tiene el ícono de "ver" (`viewRegister`/`onViewClickFunction` de `Table`) que abre `StationSourceMetadataModal`, solo lectura, con la metadata **del server de esa fila**. No hay endpoint por estación: se pide `GET api/sources-metadata/{id}` on-demand con el `metadata_source_id` que ya trae `sources-servers` (`useSourcesMetadataById`, `enabled` solo mientras el modal está abierto). Si el server no tiene metadata enlazada, el modal lo dice en vez de listar campos. El alta/edición del catálogo de metadata sigue siendo la página Sources (`SourcesServers/SourcesMetadataTable.tsx`), no la estación.
- **People** (`People.tsx`, and `src/pages/People/PeopleTable.tsx`): list via `Table` with `viewRegister`/`onViewClickFunction`. Person shape (`People` in `@types`) already has `first_name`, `last_name`, `email`, `phone`, `address`, `institution`, `position`, `photo_actual_file` (base64). Photo display reuses `ImageUploadCircle` (base64 + `UserIcon` fallback). Legacy fetch pattern.
- **Visits / station images** (`StationVisitDetailModal.tsx`, `@components/Photo.tsx`, `@components/modals/ImageModal.tsx`): images are base64 (`actual_image`). `ImageModal` serves both station and visit images via a `visit` flag. Downloads go through the shared `downloadFromBase64`/`downloadBlob` utils; the full-quality download button re-fetches the image-by-id endpoint with `original_quality=true`.
- **Visits tab (`Visits.tsx`) — migrated to TanStack Query** (`src/hooks/queries/useVisits.ts`: `useStationVisits`/`useStationVisitImages`/`useCampaigns`/`useDeleteStationVisit`; keys `["visits", id]`, `["visitImages", id]`, `["campaigns"]`). **Planned visits**: the `Visits` model has a `planned` boolean; the tab splits the single visits fetch client-side into two daisyUI tabs (Visits / Planned). The backend does NOT derive `planned` from the date — the frontend sends it: `AddVisitModal` POSTs `planned = isFutureDate(date)` (shared util in `@utils`), and `StationVisitDetailModal`'s PUT sets `rest.planned = isFutureDate(date)` (the other PUTs preserve it via the `{...visit}` spread — with PUT, omitting `planned` would reset it to `false`). Both modals show a "planned" info alert while a future date is selected, and hide the Observation-files upload button for planned visits (the backend 400s those uploads); a Celery task flips `planned` to false within the hour after the date passes.
- **Transferir visitas a otra estacion** (`TransferVisitsModal`, `@components/modals/Visit/`): dos entradas, ambas abriendo el mismo modal via `openTransferModal(visits[])` — el boton **"Transfer visits"** del header de `TableCard` (`headerActions`) manda **las visitas de la pestaña activa**, y el icono `ArrowsRightLeftIcon` de cada `VisitThumbNail` manda solo esa. El array se guarda como **snapshot** en `visitsToTransfer`: al transferir se invalida `["visits"]` y el listado se refetchea, pero el reporte tiene que seguir mostrando las visitas que se mandaron. Destino: `StationSelectList` (virtualizado) sobre el catalogo completo `useStations(api,{limit:0,offset:0})`, excluyendo la estacion actual. El endpoint transfiere igual planificadas y realizadas (`planned` se preserva) y la colision de fecha aplica contra cualquier visita del destino, asi que el boton sirve en las dos pestañas. Contrato del endpoint y manejo del 400/403 en `src/services/CLAUDE.md`.
- **Station info** edit form is `@components/modals/Station/StatsModal.tsx`: **100% data-driven via `Object.entries(STATION_INFO_STATE)`** with implicit JS insertion-order rendering, plus `inputsToDisable`/`inputsToDatePicker` arrays and conditional `MenuButton` code dropdowns. Error badges are keyed by field name; disabled fields (`api_id`, `network_code`, `station_code`) stay in state but hidden. The 4-line layout and the `AntDAZ` (antenna_azimuth) field rely on that — any layout change must preserve error keying and hidden-but-submitted fields.

## Station report (header PDF button)

`StationButtons` → `PdfContainer` opens the **backend-rendered report in a new tab**: `useStationPdf` (a `useMutation` in `src/hooks/queries/useStations.ts`, check-and-throw on `statusCode`) calls `GET api/stations/{id}/get-report-html` and writes the returned self-contained `html` into a tab pre-opened synchronously on click (popup-blocker safe); the user prints it to PDF from there. The old client-side `@react-pdf` pipeline (`Pdf.tsx`, the `loadPdf`/`loadedMap`/`loadedPdfData` states in `Station.tsx`, the map screenshot capture in `MapStationOL`) **was removed** — don't reintroduce those props/states.

## Conventions recap

- Legacy `useApi` + `useEffect` dominates these tabs; new query hooks go in `src/hooks/queries/`.
- Icons from `@heroicons/react/24/outline`. daisyUI + Tailwind, 4-space indent. Field names are English snake_case; comments/UI mostly Spanish.
- Clipboard copy goes through `useClipboard`/`CopyButton`; ECEF↔LLA conversion through `lla2ecef`/`ecef2lla` (`src/utils/coordinateConversion.ts`) — use the shared primitives, never duplicate these inline.
