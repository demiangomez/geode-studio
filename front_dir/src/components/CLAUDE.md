# Components

150+ components re-exported from the **`index.tsx` barrel**. Any new shared component must be added to the barrel and imported via `@components` / `@componentsReact`. **Exceptions:** (1) modules reachable statically from the entry (routes, `Layout`, `Nav`, `ServerStatusToast`) import concrete files, never the barrel; (2) components that reach a heavy library (`Map*OL`/`Popup`/`StationCreateMapOL`/`MapModalOL`/`TemporalBar` → ol, `RenderFileModal` → pdf.js, `QuillText` → quill, `StationModal`/`AddStation*`, `StationVisitDetailModal`, page re-exports) are **not** in the barrel and are imported by file path — re-adding one couples every page to that library and the postbuild guardrail fails. See "Eager-graph hygiene" in the root CLAUDE.md. Map components live under `map/`, modals under `modals/`, tables under `table/`, skeletons under `skeleton/`, station-specific under `station/`, menu under `menu/`.

**Before adding a component, check this directory first** — several capabilities already exist and are fragmented (root principle 2). Unify, don't duplicate.

## Shared-primitive landscape (reuse these)

- **Modals**: `modals/Modal.tsx` — daisyUI `<dialog>` opened by `showModal(id)` from `@utils`. Props include `modalId`, `close`, `size` (`sm`/`smPlus`/`md`/`lg`/`xl`/`fit`), `handleCloseModal`. `modals/ConfirmDeleteModal.tsx` is the **generic confirm dialog** — despite its name it is not delete-only: it takes `variant`, `mainMsg`/`alterMsg`, `confirmRemove`/`closeModal`, and a `type` that switches the action button (`"reset"`/`"deactivate"`/`"activate"`/`"copy_sync"` → Sync, else Remove). Reuse it for any confirm (e.g. the ETM trajectory-params sync uses `type="copy_sync"`); **do NOT add a parallel `ConfirmDialog`**.
  - Modal-open state is inconsistent: some components use local `useState({show,title,type})`, others use the Zustand `earthquakeModal` slice. Prefer the Zustand `{show,title,type}` pattern for reusable modals.
- **Date pickers**: `GregorianDatePicker.tsx` (Gregorian ↔ Year/DOY via `dateFromDay`/`dayFromDate`; `labelAbove` para sentarlo en una grilla de campos con label arriba, `portalId` dentro de un modal; **trabaja en fecha civil local**: `dateFromDay` devuelve medianoche UTC y react-datepicker usa hora local, así que al oeste de Greenwich marcaba el día anterior y al elegir sumaba uno — se convierte UTC↔local por año/mes/día, nunca por `toISOString`; el `DatePicker` va envuelto en un `div relative` para que su popup y los divs de tab-loop no entren en el flex del `label`), `DateTimePicker.tsx` (raw date+time, coupled to `useFormReducer` dispatch). **Horas sueltas (HH:MM)**: `TimeInput.tsx` — `<input type="time">` con `step` 60 (HH:MM) o 1 (HH:MM:SS); es un componente de módulo a propósito: `DateTimePicker` lo definía adentro del render y el input se remontaba en cada tecla perdiendo el foco (bug cerrado al extraerlo). New date UI builds on these — don't add inline `<input type="date">`/`type="time"` (a few stray ones remain in `StationSeriesFiltersModal`; migrate when touched).
- **Clipboard**: `useClipboard` (`@hooks`) + `CopyButton` (`@components`) are the shared primitives — never hand-roll `navigator.clipboard.writeText`.
- **Photo**: `ImageUploadCircle.tsx` renders a circular base64 photo with `UserIcon` fallback (`data:image/jpeg;base64,` prefix). `Photo.tsx` is the station-images grid (legacy fetch). File/image downloads go through the shared `downloadFromBase64` / `downloadBlob` utils (`@utils`) — don't re-implement the anchor-`download` pattern.
- **CRUD de los catálogos de Sources**: `pages/SourcesServers/SourcesCatalogModal.tsx` es el **único** modal de alta/edición/borrado de los tres catálogos (servers, formats, metadata) — eran tres copias del mismo formulario. Se parametriza con `fields` (`options` = menú de strings, `lookup` = menú de una FK que muestra un label y guarda el `id`; se vacía borrando el texto del input — `resolveLookups` manda `""` si no matchea ningún label) y los tres services; las escrituras son `useMutation`. Un catálogo nuevo se agrega como wrapper de ~50 líneas, no como modal nuevo.
- **Navbar**: `NavDropdown.tsx` (+ `NavDropdownLink`) es el dropdown compartido de `Nav` ("Campaigns" con Campaigns / Plans, "Processing and Frames", menú de usuario): abierto/cerrado, click afuera y estilos en un solo lugar. Un menú nuevo del navbar va ahí adentro, no como otro ícono suelto. Es eager (lo importa `Nav`), así que se importa por path y no está en el barrel.
- **Selects/dropdowns**: `FormControlSelect.tsx` (thin daisyUI select for string-array options), `Dropdown.tsx` (searchable country/network selector — extend, don't clone), `EtmSolutionSelect.tsx` (solution/stack selector for ETM views). `menu/Menu.tsx` es el `<ul>` de todos los combobox (input + `MenuButton` + `MenuContent`): sin hijos muestra una fila deshabilitada "No options" (`emptyText` para cambiarla), así que ningún callsite tiene que cubrir el caso de catálogo vacío, sin permiso o filtro sin matches.
- **Listas largas**: `StationSelectList.tsx` es el selector de estacion **virtualizado** (`react-window` v2 — `List` + `rowComponent`/`rowProps`, la unica dependencia que lo usa). Presentacional: recibe `stations`/`isLoading` y devuelve la elegida por `onSelect`; trae buscador propio sobre un `haystack` precalculado (`useMemo` + `useDeferredValue`), `excludeApiId` para ocultar una y `selectedApiIds` para marcar varias (el padre hace el toggle en `onSelect`). Cualquier listado de miles de filas debe construirse sobre esto, no con un `.map()` plano. Lo consumen `TransferVisitsModal`, `Campaign/StationSelectModal`, `Processing/Projects/ProcessingStationsPanel` y `Campaigns/Planner/PlannerStopsPanel`; los tres ultimos toman el catalogo de **`useStationCatalog(api)`** (`hooks/queries/useStations.ts`), que fija params y cache larga para que compartan **una sola** entrada de query en vez de una por modal — y es el unico lugar a cambiar cuando exista el endpoint liviano de estaciones.
- **Texto largo o archivo**: `FileOrTextField.tsx` es la card **"By File" / "Manual"** (dropzone o textarea) que antes vivía inline como el OTL de `StationMetadataModal`; ahora la usan ese OTL y `process_defaults`/`sestbl` de los proyectos GAMIT. Presentacional: modo (`undefined` hasta que el usuario elige), texto y `File` viven en el padre. **Al apretar "Manual" con un archivo cargado, la card lee el `File` con `file.text()` y lo vuelca en el textarea** (una vez por archivo, para no pisar ediciones al alternar) — el texto viaja entonces por el campo JSON como cualquier edición manual; "By File" sigue mandando el archivo por multipart. `height` (clase Tailwind, default `h-72`) fija el alto de la card: los proyectos GAMIT usan `h-[32rem]` porque process.defaults y sestbl se editan a mano. `Dropzone` acepta `hint`.
- **Mapa de selección (`map/MapModalOL.tsx`, por path)**: además de `markerType`/`handleDrawPolygon`/`setShowMapModal` acepta props **opcionales** que no cambian a Earthquakes ni a Add Station: `title`, `onSave(selection | null)` (la selección se confirma **solo con Save**; tacho o cierre = cancelar; `handleDrawPolygon` pasa a ser opcional), `initialSelection` (reabre con el marcador+radio o el polígono guardados), `showStations` (en modo polygon dibuja el catálogo entero con `StationCreateMapOL` y su ícono normal; con polígono activo las de afuera quedan al 30% de opacidad, igual que el filtro temporal sin "Hide"; `StationCreateMapOL` acepta `showAll` + `polygon` además de marker+radio, y **`highlightedApiIds`** (un `ReadonlySet<number>`: todo lo que no esté en el set se atenúa igual que fuera del polígono — los dos criterios se combinan). En modo polygon hay **uno solo por vez**: empezar otro borra el anterior y el hint lo dice. **`map/StationListMapModal.tsx`** (por path) es el modal de **solo lectura** que muestra una lista de estaciones resaltada sobre el catálogo atenuado, encuadra la vista a las de la lista (`view.fit` en el primer resize con tamaño real, porque el `<dialog>` abre después del mount) y cuenta las que no tienen coordenadas; lo abre "View on map" en `ProcessingStationsPanel`. No tiene Save: se cierra por la ✕. El tooltip flotante de los tres mapas es **`map/StationTooltip.tsx`** (forwardRef), no un `<div style>` inline por mapa. La **leyenda de tipos/estados** es **`map/StationLegendContent.tsx`** (listas de types + statuses; `compact` para superponerla dentro de un mapa): `StationMetadataLegend` es solo la cáscara draggable (`react-rnd`) que usa `Main`, y `StationListMapModal` la muestra compacta adentro del contenedor `relative` del mapa — no como panel flotante, porque dentro del `.modal-box` un `Rnd` agranda el scroll del modal y el top layer del `<dialog>` tapa cualquier portal a `body`. Comparte con `Campaigns/Planner/CampaignPlanMapOL` el **`pinIconUrl(color)`** de `@olUtils` (el pin SVG para marcadores que no son estaciones). Las listas de `net.code` (`mergeStationCodes`/`removeStationCode`/`stationCodeOf`) viven en `utils/stationCodes.ts`, no en cada feature.
- **Feedback**: `Alert.tsx` (inline error/success with error detail), `Message.tsx` (a.k.a. Toast — fixed top-right singleton, no queue). **Botones de accion de modales**: los anchos salen de **`buttonSizes`** y los roles de **`modalActions`** (`src/utils/index.ts`, al lado de `modalSizes`) — `container` / `primary` / `destructive` / `secondary`. Son `min-w` en **px**, no fracciones: `modalSizes` ya es un porcentaje del viewport, asi que un `w-6/12` adentro ata el boton al monitor (552px a 1920, 744px a 2560) y ademas hace saltar el boton cuando entra el spinner. Ningun modal nuevo o modificado deberia volver a hardcodear anchos. Los colores los fija el rol, no el callsite. **Orden del pie: destructivo a la izquierda, primario a la derecha** (`Remove` … `Submit`) — es lo que ya hacian 11 de los 12 modales con ambos botones, asi que la convencion se escribio, no se invento. **No se agrega un boton de Cancel/Close**: los modales se cierran por click afuera (`close={false}`) o por la ✕ (`close={true}`); un tercer control seria una tercera forma de hacer lo mismo. `Pagination.tsx` for tables. `table/Table.tsx` + `table/TableCard.tsx` are the generic table (delete/alter/view/visits/multiselect buttons, `viewRegister`). El `size` de `TableCard` es un **tope** (`max-width`, `width: 100%`), no un ancho fijo: en px define cuánto mide la tabla en un monitor grande (Users/Roles están calibradas para entrar lado a lado en 24") y en pantallas más angostas el card se encoge y la tabla scrollea adentro (`overflow-x-auto` de `Table`) en vez de desbordar el body — no volver a `width` fijo. `TableCard` tiene dos slots libres en el header: **`headerContent`** (izquierda, junto al titulo — p.ej. las pestañas de Visits) y **`headerActions`** (derecha, antes de los botones de alta — p.ej. "Transfer visits"); los botones de alta siguen atados a `setModals`, asi que cualquier accion que necesite otro handler va por `headerActions`.

## Forms & error handling

- Form state: **`useFormReducer`** (`@hooks`) — actions `set` / `change_value` / `change_array_value` / `list_to_clear` / `clear`. Reducer initial-state templates live in `src/utils/reducerFormStates.tsx`. Some components (`Photo`, `TimeSeriesParams`) use local `useState` instead — divergent, prefer the reducer.
- Services swallow errors via `useApi` and return a fake `{status:'error', statusCode, response}`; **callers check `statusCode`, they don't try/catch.** Surface results through `Alert`: el mensaje es un **`AlertMsg`** (`@types`: `{status, msg, errors?}`) y el error de una mutation/query se convierte con **`toAlertMsg(error)`** (`@utils`, en `apiError.ts`) — no volver a escribir el `instanceof ApiError ? {...} : {status: 500, ...}` en cada modal (lo usan Processing y el Campaign Planner). **In TanStack hooks the check goes *inside* the `queryFn`/`mutationFn` and must `throw` on failure** — otherwise `isError` never fires and `useQuery` caches the error object as data (pattern: `useStationPdf`).

## Conventions

- daisyUI + Tailwind, **4-space indent**. Icons from `@heroicons/react/24/outline`. daisyUI `tooltip`/`tooltip-right`/`tooltip-bottom` classes (+ `data-tip`) are the tooltip mechanism (the fixed sidebar relies on them). Spanish comments/UI; English field names.
