# Services layer

`index.ts` is a single ~2000-line file with 100+ service functions wrapping Axios calls. Imported as `@services`.

## Contract (follow exactly)

- Every service is `async function <verb><Noun>Service<T>(api: AxiosInstance, ...args): Promise<T>` — **`AxiosInstance` is always the first arg** (except the unauthenticated `loginService`/`refreshTokenService`, which use `axiosInstanceUnauth`).
- Internally: `try { ... } catch (e) { return Promise.reject(e) }`. But **`useApi` (`src/hooks/useApi.tsx`) intercepts rejections and resolves a fake object `{ status: 'error', statusCode, response, msg }` instead of throwing.** So **callers check `statusCode` / `'status' in res`, never `try/catch`.** (A code comment notes this should eventually become a real `Promise.reject`.) The one exception: a client abort (`error.code === AxiosError.ERR_CANCELED`, i.e. TanStack cancelling a query whose `queryFn` consumed `signal`) **is rejected as-is** — it is not a response and must not trigger the global server-error toast; legacy callers that pass a `signal` need a `try/catch` for it (`PopupChildren`). **In TanStack hooks that check must live *inside* the `queryFn`/`mutationFn` and end in a `throw`** — otherwise the failure is silent (`isError` false, no `retry`, no `onError`) and `useQuery` caches the error object as data. Pattern: `useStationPdf` (`src/hooks/queries/useStations.ts`).
- Query params are serialized with `transformParams` (`@utils`) — it skips `undefined` values, so optional params can be passed directly. Some services build params manually (`getRinexService`, `getStationTimeSeriesService`) — prefer `transformParams` for new ones.
- Verb prefixes: `get` / `post` / `put` / `patch` / `del`. Response types use a `Data` suffix (`NetworkData`, `StationImagesData`, …) and live in `@types` (`src/interfaces/index.d.ts`).
- File uploads use `FormData` + `multipart/form-data` (see `postStationsFilesAttachedService`).

## Endpoint catalogue (key areas)

- **Time series / ETM**: `getStationTimeSeriesService(api,id,params,json)` → `{time_series, etm_params, download_filename, debug_output}` (`debug_output` = console log of the ETM run, plain text; a 400 also includes it when the ETM ran partially before failing, e.g. invalid stack — absent on params-validation 400s); `post`/`reset` for `Polynomial`/`Periodic`/`Jump` take `(api,id,solution,stack,params)`; `deleteTimeSeriesJumpService(api,id,solution,{Year,DOY})`; **`putTimeSeriesJumpService(api,id,solution,stack,params)`** → `PUT .../set-jumps` for **editing** a jump (body = new jump + `old_Year`/`old_DOY`; backend does delete+create atomically); `getJumpTypesService(api)`; `getStackNamesService(api,id)`. **ETM config catalogs:** `getSolutionTypesService(api)` → `GET api/time-series-config/solution-types` (`{solution_types:[{id,type}]}`: GAMIT/PPP/NGL/DRA), `getAdjustmentOptionsService(api)` → `GET api/time-series-config/adjustment-options` (`{adjustment_models, covariance_functions}`), and `getModeObsTypesService(api)` → `GET api/time-series-config/mode-obs-types` (`{mode_obs_types:[{id,type,description}]}`: MODEL/OBSERVATION — `description` ignored; backend accepts id **or** type for the coordinates `mode_obs` param, we send `type`). Wrapped in `useSolutionTypes` / `useAdjustmentOptions` / `useModeObsTypes` (`src/hooks/queries/useTimeSeriesConfig.ts`). The time-series query + `buildTimeSeriesParams` live in `useStationTimeSeries.ts`.
- **Networks**: `getNetworksService`, `postNetworkService(api,{network_code,network_name})` (create), `putNetworkService(api,id,{network_code,network_name})` (edit — the backend **requires `network_code` in the body too**, not just `network_name`), `delNetworkService` (exists but **do not surface delete** in the Networks UI — deliberate product decision).
- **Station info**: `get`/`post`/`put`/`del` `StationInfoService` + file variants.
- **People**: `getPeopleService`, `postPeopleService`, `patchPeopleService` (FormData w/ photo), `delPeopleService`, `mergePeopleService`.
- **Images (full-quality download)**: `getStationImageByIdService(api,id)`, `getStationVisitsImagesByIdService(api,id)` (+ list/post/del and `patch...Description`). The by-id variants accept `?original_quality=true` to return the full-resolution base64 — that's what the full-quality download buttons re-fetch with.
- **Visit transfer**: `postTransferVisitsService(api, {visits:[ids], destination_station: apiId})` → `POST api/visits/transfer` (JSON, no FormData) mueve las visitas con todos sus archivos a otra estacion. Responde un **reporte por visita** `{transferred:[{visit,date}], rejected:[{visit,date,error}]}` con **200** (al menos una transferida) y con **400** (ninguna — tipicamente colision de fecha, la DB tiene `unique(station,date)`). El wrapper `useTransferVisits` (`useVisits.ts`) devuelve ese reporte como `data` en ambos casos y solo throwea `ApiError` cuando la respuesta no lo trae (403 sin permiso — el cluster `transfer-visits` del rol —, body invalido, 500). El permiso **no se pre-chequea en el front**: el boton siempre se ve y el 403 lo pinta el toast global de `ProtectedRoute` mas el `Alert` del modal.
- **Catalogo de estaciones (`only_metadata`)**: `GET api/stations?only_metadata=true` devuelve la **forma reducida** —`api_id, network_code, station_code, station_name, country_code, lat, lon, status, type, date_start, date_end, has_gaps, has_stationinfo, gaps`— o sea todo lo que el mapa dibuja/filtra y lo que los selectores buscan. La forma completa agrega `harpos_coeff_otl` (coeficientes OTL, de 1 a 3 KB **por estacion**) mas `auto_x/y/z`, `max_dist`, `dome`, `marker`, `height`, `plate`. Sin el flag el catalogo completo pesa ~12,7 MB sin comprimir, lo que en los enlaces satelitales de la Antartida son minutos.
  - **Lo mandan** los consumidores de lista: `useStationCatalog` (los tres selectores de estacion), el `useStations` de `Main.tsx` (mapa) y el de `MapModalOL`.
  - **No lo mandan** las lecturas de detalle: `useStation` (`useStationMetadata.ts`) y los `getStationsService` de `Station.tsx`, que filtran por `network_code`+`station_code`. Es critico: `StationMetadataModal` edita `harpos_coeff_otl`, y si lo recibiera vacio el PATCH **borraria los coeficientes en la base**.
  - En `StationData` los campos que el flag no devuelve estan marcados **opcionales**, para que TS avise si una vista de lista intenta leerlos.
- **`useMetadata` es un paquete de 6 queries, no un catalogo**: monta `stationTypes`, `stationStatuses`, `monumentsTypes`, `stationRoles`, `networks` y `countries` de una. Como no se puede llamar a `useQuery` dentro de un `if`, desestructurar solo uno **no apaga los otros cinco**: hay que pasar **`only`** (`useMetadata(api, { only: ["types","statuses"] })`), que los deja en `enabled: false` y evita el request entero. Importa porque pesan muy distinto: `monument-types` trae `photo_file` en base64 (~480 KB) y `station-types` los iconos (~49 KB). Sin `only`, la pagina de Networks bajaba 577 KB para mostrar una tabla de 7 KB.
  - `only_metadata=true` sirve **ademas**, no en vez: achica el payload de `/api/monument-types` (saca `photo_file`), pero el round trip se sigue pagando. Primero `only`, despues `only_metadata`. Quien **si** necesita las fotos en la lista es `Overview/MonumentsTable` (columna "Photo", y alimenta el preview de `MonumentModal`); la foto del monumento elegido en `StationMetadataModal` va por `useMonumentPhoto(id)`, que es by-id.
- **Sources (3 catálogos + el join por estación)**: `sources-servers` (RINEX), `sources-formats` y **`sources-metadata`** (`get`/`getById`/`post`/`put`/`delete` `SourcesMetadataService`), todos con la misma forma `{count, total_count, data}` y los mismos permisos. `sources_metadata` es la config con la que **geode (`SyncMetadata.py`) baja los archivos de metadata** de la estación (IGS site logs, station.info) — **la web no descarga nada, sólo administra y muestra**. Su objeto es igual al de un server pero con **`id`** en vez de `server_id`, y `username`/`password`/`path`/`format` nulables (el backend guarda `""` como `null`). `sources-servers` gana **`metadata_source_id: number | null`** (mandar `""`/`null` para "sin metadata"); una misma metadata la comparten varios servers, por eso es catálogo y no un campo embebido. Borrar una metadata referenciada por un server da **400** (FK).
  - **Protocolos válidos: `FTP`, `FTPA`, `SFTP`, `HTTP`, `HTTPS`** — **`FTPS` no existe** (la DB lo rechaza con 400); el modal lo ofrecía y se reemplazó por `FTPA` (FTP activo). La lista vive en `SOURCES_PROTOCOLS` (`src/pages/SourcesServers/sourcesCatalog.ts`), no se hardcodea por callsite.
  - **Los placeholders del path de metadata no son los de RINEX**: van sin `$` — `{station}`/`{STATION}`/`{stn}`/`{STN}`/`{network}`/`{net}` (p. ej. `/pub/station/log/{station}_*.log`). Un `${station}` al estilo RINEX **no se reemplaza**; por eso el input lleva el hint.
  - Las lecturas van por **`src/hooks/queries/useSources.ts`** (`useSourcesServers`/`useSourcesFormats`/`useSourcesMetadata`/`useStationSources`/`useSourcesStationsByServer`): los tres catálogos los comparten la página Sources y la solapa Sources de la estación, así que se cachean una vez. Las escrituras son `useMutation` dentro de `SourcesCatalogModal` y refrescan vía **`useInvalidateSources()`** (invalida `["sources"]` entero: un server referencia una metadata y una source station un server, así que invalidar sólo una rama deja las otras viejas).

- **Reference Frames (`api/reference-frames`)**: sólo lectura desde el front — `getReferenceFramesService(api)` → `{count, total_count, data: ReferenceFrameData[]}`, sin filtros (orden `frame_name`; la búsqueda es client-side sobre el `data` completo, el catálogo es chico). El backend también expone POST/PUT/DELETE, pero el requerimiento es una **vista** ("Create a window view reference frames"), así que no hay modal ni escrituras. `stacks_count` (read-only, calculado) cuenta las filas de `stacks` con ese `frame_name`; sin índice en `stacks.name` es un scan completo por frame y el listado tarda. Hook: `useReferenceFrames` (`hooks/queries/useReferenceFrames.ts`); página en `src/pages/Processing/` bajo el menú "Processing and Frames".
- **Processing projects (`api/gamit-projects`, motor-agnóstico)**: los servicios reciben el **endpoint desde el registro de motores** (`src/pages/Processing/Projects/engines.ts`) para que `pages_projects` reutilice los mismos: `getProcessingProjectsService(api, endpoint, params)` → `{count, total_count, data}` paginado (`limit`/`offset`, búsqueda `?project=` contiene sin distinguir mayúsculas), `post`/`patch`/`del` `ProcessingProjectService(api, endpoint, ...)`. El guardado va en **dos requests cuando hay archivo** (`useSaveProcessingProject`): un POST/PATCH **JSON** con todas las columnas (`null` en los opcionales vacíos, `station_list`/`systems` como arrays, incluso vacíos) y después un PATCH **multipart solo con `process_defaults_by_file` / `sestbl_by_file`** (la UI es el par "By File"/"Manual" del OTL). Multipart no puede expresar `null` ni una lista vacía (sin la clave el backend no toca el campo) y un `""` en `overconst_action` rompe el CHECK de Postgres (`IS NULL OR IN (...)`), por eso no se manda todo junto. Si el JSON se guarda y el archivo falla (p.ej. no UTF-8), el hook devuelve `fileError` y el modal queda en edición de ese proyecto para reintentar sin duplicarlo. `station_list` guarda `net.stnm` con el case exacto de la DB (el backend matchea sin distinguir mayúsculas, deduplica y devuelve 400 listando hasta diez desconocidos). Borrar un proyecto borra en cascada sus soluciones en `gamit_soln`, `gamit_soln_excl`, `gamit_subnets`, `gamit_stats` y `gamit_antenna_residuals` (sin conteos: `gamit_soln` tiene 20M de filas); renombrar cascadea por FK. Hooks en `useProcessingProjects.ts` (lista con `keepPreviousData`, mutaciones, `useInvalidateProcessingProjects`).
  - **`postProcessingStationListService(api, params)`** → `POST api/processing-station-list`: resuelve filtros (`station_type` id, `country_code` ISO3[], `lat`+`lon`+`distance_km` juntos, `polygon` [{lat,lon}] ≥3) combinados con AND, al menos uno obligatorio; es POST solo porque el polígono no entra en la query string, **no crea nada**. Devuelve `{count, station_list, stations}` (`stations` con la forma `only_metadata` para dibujarlas). Las redes `?` nunca se incluyen. Wrapper `useResolveProcessingStations` (un `useMutation`: lectura on-demand que se acumula en el formulario, no se cachea).
- **Campaign planner (`api/campaign-planner`, `api/campaign-plans`)**: contrato completo en `../gps/docs/contrato-campaign-planner.md`. `postCampaignPlannerService(api, params)` → `{html, plan}`: corre el planner de geode (Nominatim + OSRM, **segundos**, no guarda nada); `getGeocodeCityService(api, q)` → `{name, lat, lon}` para ubicar una ciudad en el mapa antes de planificar. CRUD de parámetros guardados (tabla `campaign_plans`, **sin relación con `campaigns`**): `getCampaignPlansService(api, params)` paginado con búsqueda `?name=` (icontains), `getCampaignPlanService(api, id)` (deep link `/campaign-plans/:id`), `post`/`put`/`del` `CampaignPlanService`. Los `stations` (`net.code`) se validan contra la tabla sin distinguir mayúsculas y se normalizan al código exacto de la DB; un código desconocido da **400 `attr: "stations"`** listándolo. Mismos campos en el planner y en el CRUD (`CampaignPlanParams`, más `name` e `id` en `CampaignPlanData`); `new_sites` admite cuatro formas (`"lat,lon"`, `"Ciudad, País"`, `{name, lat, lon}`, `{name, city}`). Errores del motor (estación desconocida, ciudad no geocodificable, OSRM timeout) llegan como **400 con `attr: null`** y se muestran tal cual. Permisos: cluster `campaigns` (`read` planifica y geocodifica; `read-write` guarda). Hooks en `hooks/queries/useCampaignPlans.ts` (planner y geocode son `useMutation`).
- **Earthquakes / metadata**: `getEarthquakesService`, `getAffectedStationsService`, `getNetworksService`, `getCountriesService`.
- **Station report**: `getStationReportService(api, stationApiId)` → `GET api/stations/{id}/get-report-html` returns `{ html }` (self-contained HTML). Consumed by the `useStationPdf` mutation (`src/hooks/queries/useStations.ts`) from `PdfContainer`: opens the HTML in a new tab and the user prints it to PDF. This **replaced** the old client-side `@react-pdf` generation.
- **Coordinates by epoch**: `getStationCoordinatesService(api, id, params)` → `GET api/time-series/{id}/coordinates?solution&stack(if GAMIT)&mode_obs={MODEL|OBSERVATION}&date_format={gregorian|doy}&...`. Gregorian sends `year/month/day`; DOY sends `year/doy`. Returns `StationCoordinatesData` (`{xyz, lla, source, sigmas}`). Driven from the **"Query"** button in `TimeSeries.tsx` → `QueryCoordinatesModal` (a `useMutation`). `mode_obs`: MODEL = ETM-modeled position, OBSERVATION = observed position that date.
- **Bulk ETM download**: `postBulkTimeSeriesDownloadService(api, stations, signal)` → `POST api/time-series/bulk-download` `{ stations }` with `responseType: 'blob'` → ZIP. Success is detected by `data instanceof Blob` (the `useApi` interceptor turns errors into plain objects, so a Blob means the download worked); filename comes from `Content-Disposition`. Driven from `DownloadAffectedStationsModal` (a `useMutation`).
- **RINEX download**: `getRinexDownloadService(api, rinexApiId, signal?)` → `GET api/rinex/{api_id}/download` with `responseType: 'blob'`. Same Blob-vs-error handling as the bulk download (shared `blobResponseToResult` helper, `FileDownloadResult`). geode fetches the file from the station's RINEX sources on demand, so it can be slow and 4xx when no source has it. Consumed by `useDownloadRinex` (`hooks/queries/useRinex.ts`, a `useMutation`) from the per-row DOWNLOAD column of the station Rinex tab.
- **ETM trajectory-params sync (`copy_params`)**: `setCopyParamsService(api, stationId, solution, copyParams)` → `POST api/time-series-config/{stationId}/{solution}/set-copy-params` `{ copy_params: boolean }` persists the "COPY TRAJECTORY PARAMETERS TO OTHER SOLUTIONS" checkbox; its initial value comes from `etm_params.copy_params` in the time-series GET. Enabling mutates the other solutions' params in the DB, so a successful enable invalidates `["stationTimeSeries", stationId]` (full UX flow in `src/pages/Station/CLAUDE.md`).

When adding a new service, choose the TanStack tool deliberately (root principle 3): wrap it in a **`src/hooks/queries/` hook** if it's a cacheable/shared read (incl. static reference catalogs); use **`useMutation`** for writes and on-demand user-triggered reads (e.g. the coordinates Query, the ETM JSON export). Don't hand-roll `useApi`+`useEffect`+`useState`.
